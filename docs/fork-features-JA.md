# フォーク固有機能の保全ガイド

**言語:** [English](fork-features.md) · [简体中文](fork-features-ZH.md) · [日本語](fork-features-JA.md)

## この文書の目的

この文書は、CJK フォークで意図的に維持している動作を記録し、今後の upstream マージで失われないようにするためのものです。
一般的な機能一覧ではなく、類似機能が upstream に一切存在しないと主張するものでもありません。
マージ時には、ユーザーから見える機能上の約束と、競合のないマージでも失われ得る実装上の不変条件を区別してください。

以下の高リスク箇所で upstream 版を採用する前に、API やビルド結果だけでなく実際の動作を比較する必要があります。
ビルドが通るだけでは、フォークの契約が保たれたことにはなりません。

## ユーザーから見えるフォーク固有機能

### 1. CJK UI とグリフ範囲

- 製品版 UI は簡体字中国語、繁体字中国語、日本語、英語に対応します。
- 中国語 2 種と日本語の翻訳は、フォント管理、更新、エラー、リカバリー関連表示を含む端末上の一連の操作を網羅します。
- 内蔵 CJK UI グリフは、手作業の文字一覧ではなく、出荷対象の翻訳データと必要な UI 記号から生成します。
- SC 版と TC 版のリリース環境では、それぞれの既定言語と生成フォントの文字範囲を維持します。
- UI の不足グリフは互換性のある SD フォントで補完できますが、ラテン文字の UI メトリクスを不用意に変えてはいけません。

代表的なコミット: `2d1148ff`、`619b6dcd`、`962c06ff`、`52514474`。

### 2. 本文用と UI 用で独立した SD CPFont

- 本文と端末 UI には、別々の SD `.cpfont` ファミリーを割り当てられます。
- 一方の選択、置換、解除、読み込み失敗によって、もう一方の設定が暗黙に上書きされてはいけません。
- 内蔵ファミリーはフォールバックとして有効ですが、内蔵の本文ファミリーを SD ベースの UI ファミリーとして自動的に扱ってはいけません。
- UI フォールバックには実用的な CJK グリフ範囲が必要で、UI メトリクスに適した正確なサイズを使います。
- カタログの出入り、低メモリからの復旧、再起動、SD レジストリの再検出後も、選択したフォントを保持します。

代表的なコミット: `06c2686a`、`4c3c40ce`、`ab5cfb6d`、`dfc5fc54`。

### 3. 端末内フォントカタログと安全なインストール

- owner/repository 形式や HTTPS マニフェスト URL を含む、複数のフォントリポジトリに対応します。
- カタログ情報と更新日時を閲覧し、オンラインのファミリーをプレビューして、選択サイズまたはファミリー一式をインストールできます。
- 本文用・UI 用パッケージは、ステージングを伴うトランザクション方式で置換します。中断や失敗が起きても、最後に利用できたファミリーを破壊しません。
- Web からのファミリーアップロードにも同じトランザクション原則を適用します。
- ダウンロードサイズに上限を設け、必要なファイルは正規の CPFont v4 構造として検証し、マニフェストの SHA-256 と照合します。
- 大きなマニフェストはストリーミング解析し、フォント本体のダウンロードや描画の前にマニフェスト用メモリを解放します。
- HTTPS リダイレクト、TLS バッファ、range ダウンロードは ESP32-C3 のヒープ制約に合わせて制限します。
- ネットワーク、検証、プレビュー、インストールの処理中もキャンセル可能である必要があります。
- 低メモリ時の自己復旧で設定済み UI ファミリーを失ったり、一時プレビュー・置換ファイルを残したりしてはいけません。

代表的なコミット: `66dd6348`、`8ea12890`、`0eb39e3e`、`4c2016f2`、`dc9e2f6b`、`6654c172`、`ccedc6ef`。

### 4. CJK を考慮した組版と操作応答性

- EPUB と TXT のレイアウトは、ラテン文字の空白を前提にせず、CJK の改行と約物の禁則を考慮します。
- 両端揃えでは CJK の改行可能位置を伸縮可能な間隔として扱いますが、見えるラテン空白は挿入しません。
- 任意の段落字下げはおよそ全角 2 文字分で、ページネーションとキャッシュ無効化にも反映します。
- CJK 向けの広いポイントサイズ群は、壊れやすい配列上の番号ではなく、実際にインストールされたサイズで選択します。
- SD グリフ読み込みはバッチ化または事前読み込みし、CJK ページで文字ごとにランダム SD シークが発生する状態を避けます。
- ブロッキング処理を始める前に、索引作成中であることを画面へ表示します。
- セクション構築、グリフ収集、画像デコード、グレースケール描画、索引作成、ページ描画は安全な境界でキャンセル可能にします。
- 入力と activity 遷移を古いバックグラウンド処理より優先し、失効した描画が新しい画面を後から上書きしないようにします。

代表的なコミット: `4401cf40`、`15a7959a`、`a3e39099`、`d10e84cb`、`0db37e73`、`775ef4cc`。

### 5. ダークモードの表示品質

- ダークモードで見える更新には、通常のページ移動、復旧・縮退経路、モーダル画面、スリープ遷移、低メモリ処理を含めて `DarkRedrive` を使います。
- upstream のライトモード経路が `HALF_REFRESH` や通常の `FAST_REFRESH` を使っているという理由で、ダークモードを同じ方式へフォールスルーさせてはいけません。
- 部分・ウィンドウ更新ではダーク用の再駆動経路を使い、論理ウィンドウを正しい物理パネル座標へ変換します。
- 本文画像の極性を維持します。暗い背景を反転しても、表紙やページ画像を二重反転させてはいけません。
- クロップした表紙の範囲を完全に塗り、前フレームの縁が残らないようにします。

代表的なコミット: `76c0a1bc`、`d720891b`、`d92649d5`、`489e028a`、`2b79de3d`。

### 6. UI 全体の縦向き反転と向きに追従する入力

- リーダーの向きと UI の向きは、別々の永続設定です。
- リーダーは全方向を扱い、通常の UI activity は意図的に Portrait と Portrait Inverted のみを扱います。
- UI 反転はリーダーだけでなく、ホーム、設定、ダイアログ、キーボード、Wi-Fi、フォントカタログ、更新画面を含む UI 全体に適用します。
- 入力マッピングは、古いリーダー設定ではなく、実際に描画している画面方向に従います。
- 反転時も、ボタンヒント、安全領域、バッテリー・ステータス位置、選択更新、タッチから論理座標への変換を正しく保ちます。
- 2 つの設定を 1 つの enum に「簡略化」したり、ホーム画面にリーダーの横向きを継承させたりしてはいけません。

代表的なコミット: `106af11f`、`47b838ff`、`78154ba9`、`39889436`。

### 7. 遅延実行・キャンセル可能なホーム表紙処理

- 未生成の表紙に重い処理が必要でも、先にホーム画面を操作可能にします。
- 表紙サムネイル生成は遅延実行し、入力や activity の変更時にキャンセル可能にします。有効な既存キャッシュは再利用します。
- 描画世代とスナップショットにより、移動後やジオメトリ変更後に古い表紙処理が描画することを防ぎます。
- 選択状態の部分更新は既知のパネル状態を基準にし、安全な領域だけを書き換えます。
- ダークモードの部分更新でも、表紙の極性とバッファ復元を正しく維持します。
- キャッシュミスや中断時は、カードが半描画のまま残るのではなく、完全で操作可能なホーム画面へ縮退します。

代表的なコミット: `27ae3243`、`e75102a4`、`9b27173a`、`9beff5d0`、`5f9854d8`。

### 8. 応答性を維持する Web とアップロード

- 長い HTTP、WebDAV、ファイル一覧処理では、必要に応じてタスク WDT を安全に更新し、適切な箇所で `yield()` します。
- handler の終了後に実行され得る Web 応答は、有効期間の長い状態を保持し、短命なバッファやオブジェクトを遅延コールバックで参照しません。
- 設定ページのデータ読み込みと応答生成は、メインループや表示・入力処理を長時間止めないよう、ノンブロッキングまたは十分短い単位に保ちます。
- アップロードは有界バッファでストレージへストリーミングし、低メモリ経路を維持します。ファイル全体と同じ大きさの RAM を要求してはいけません。
- 不完全、タイムアウト、上限超過、失敗したアップロードで、有効な既存ファイルを置換しません。
- Web、WebDAV、描画、フォント、永続化からの SD アクセスは、リポジトリの直列化・ロック規約に従います。

代表的なコミット: `a946c83a`、`27ec21db`、`128d5236`、`f6deae44`。

### 9. Wi-Fi の古いスキャン状態からの復旧と CJK 地域のホットスポット検出

- 新しい非同期スキャンの前に、Arduino Wi-Fi 層に残った以前のスキャン状態を消去します。
- 接続失敗、スキャン中断、スマートフォンのホットスポット変更後も、再起動せず復旧できるようにします。
- 接続前のスキャンでは国コード `CN` を初期値として、チャンネル 12 と 13 を検出可能にします。
- IEEE 802.11d を有効に保ち、アクセスポイントが通知する規制ドメインを無線側で採用できるようにします。
- この処理を恒久的な規制ドメイン固定へ変更したり、単なる地域依存定数として削除したりしてはいけません。

代表的なコミット: `accf1ee0`。

### 10. SD フォント・FileBrowser の性能と SD 直列化

- FileBrowser の一覧描画ホットパスでは、完全パスやテキストの反復処理、不必要な SD 読み込みを避けます。
- SD ベースの UI・本文フォントでは、ランダムアクセスとヒープ変動を抑えるキャッシュ・事前読み込みを維持します。
- 共有 SD 状態に関係するファイルの open/close 順序は直列化します。一見無害な早期 close でも別タスクと競合する可能性があります。
- 長いディレクトリ走査やファイルコピーでは、定期的に実行権を譲り WDT を更新します。
- エラー・キャンセル経路ではフォントとファイルのリソースを解放し、レジストリや UI フォント状態の整合性を崩しません。

代表的なコミット: `16a59f4a`、`361aee32`、`c9aad6db`、`f6deae44`。

### 11. SD ファームウェア、リカバリー、安全なアップロード

- 通常の設定画面から SD カード上のファームウェアをインストールできます。
- 通常 UI へ入れない場合、起動時に文書化されたボタン組み合わせを押し、SD ファームウェア選択画面へ直接移動できます。
- 独立したリカバリー環境とパッケージ作成フローをビルド可能に保ちます。詳しくは [SD Recovery Firmware](recovery-firmware.md) を参照してください。
- 書き込み前にイメージ形式、対象チップ・端末、パーティション互換性、安全なサイズを検証します。
- アップロード・インストール処理は、必要な bootloader、partition table、factory、デュアル OTA レイアウトの前提を維持します。
- 成功時は意図した OTA イメージを起動し、失敗時も端末を復旧可能な状態に保って有用なエラーを表示します。
- ファームウェア転送はストリーミングかつ WDT セーフに行い、大きな一括割り当てに依存しません。

代表的なコミット: `5717374e`、`bf796a63`、`3e993191`、`e0ff0c9a`。

### 12. 永続設定の互換性と Calibre の古い情報の消去

- 既存の保存設定は互換性境界です。JSON キー、enum の数値的意味、既定値、負の SD フォント ID、移行動作を維持します。
- 特に、リーダー方向と UI 方向のインデックス、スリープ画面 enum の順序、キーボードレイアウトのビット、フォント役割の選択を変えてはいけません。
- 新規フィールドには後方互換の既定値を設定し、設定 schema/list に登録します。
- 応答性のため読書位置とクラッシュ復旧情報の書き込みを遅延できますが、ディープスリープなど永続化境界の前には完了させます。
- Calibre 接続 UI に、古いセッションや廃止された認証フローの管理トークンを表示してはいけません。

代表的なコミット: `6e4d0e53`、`0299a89c`、`ee3d714d`、`b0049cba`。

## マージ時に守る実装上の不変条件

上記はユーザー向け機能です。それを維持するため、次の実装条件を守ります。

1. 生成ファイルは引き続き生成物として扱います。翻訳 YAML、グリフ入力、生成スクリプトを変更してから再生成します。
2. 本文用と UI 用のフォント ID・状態は、設定、レジストリ検出、renderer 初期化、プレビュー、インストール、ロールバックの全段階で独立させます。
3. フォントパッケージは、完全なダウンロード、サイズ・ハッシュ検証、CPFont 検証、原子的または段階的置換が終わるまで有効化しません。
4. マニフェストとフォントのダウンロードには、明示的なバイト上限、キャンセル確認、WDT 更新、有界メモリのストリーミング処理を設けます。
5. ダークモードの可視更新は、バッファまたはウィンドウの `DarkRedrive` へ明示的に分岐させます。ライトモード経路への暗黙のフォールバックは不可です。
6. 全対応方向で、論理から物理へのウィンドウ変換と画像の極性を維持します。
7. 長い描画、索引、表紙処理は描画世代またはキャンセル条件を持ち、framebuffer を確定する直前にも確認します。
8. メインループの入力ポーリングを、ブロッキング描画、通信、表示待ち、SD 処理の後ろへ移動しません。
9. 共有 SD 操作は `HalStorage` と既存のロック規約に従い、複数タスクが生の SD handle を並行保持する実装を避けます。
10. 永続 enum 値と JSON キーはデータ形式 API です。C++ 上で内部実装に見えても変更には互換性検討が必要です。
11. ファームウェアは消去・書き込み前に検証し、対応 Xteink ハードウェアの起動・パーティション契約を維持します。
12. Web・Calibre の機密値やセッション由来値は、所有セッションの終了時に消去します。

- [ ] 2 つ以上のリポジトリでプレビューとインストールを行い、キャンセル、不正 SHA-256、無効 CPFont、中断、低ヒープを試す。

## この文書の保守

フォーク機能を意図的に削除・置換した場合、または upstream に同等で検証済みの実装が入った場合に、このガイドを更新してください。
長い修正履歴を並べるより、代表的なコミット 1 件と最小限の高リスクパスを記録します。
3 言語版の意味を揃え、ファイル名を変更した場合は上部の相互リンクを再確認してください。
