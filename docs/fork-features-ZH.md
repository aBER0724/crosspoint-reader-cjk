# 分支特性保全指南

**语言：** [English](fork-features.md) · [简体中文](fork-features-ZH.md) · [日本語](fork-features-JA.md)

## 文档目的

本文记录 CJK 分支有意保留的行为，后续合并上游代码时不得意外覆盖。
它不是普通的功能列表，也不表示上游完全没有相近功能。
合并时应以此区分“用户能够直接感知的承诺”和“即使无冲突合并也可能丢失的实现不变量”。

接受下列高风险路径的上游版本前，必须比较实际行为，而不能只看 API 是否一致、是否能够编译。
构建成功并不能证明分支契约仍然完整。

## 用户可见的分支特性

### 1. CJK 界面与字形覆盖

- 正式界面支持简体中文、繁体中文、日文和英文。
- 简中、繁中和日文翻译覆盖完整设备流程，包括字体管理、更新、错误提示以及恢复相关标签。
- 内置 CJK UI 字形应从正式翻译语料和必要 UI 符号自动生成，而不是依靠难以维护的手工字符表。
- 简中与繁中发布环境必须保留各自预期的默认语言和生成字体覆盖范围。
- UI 缺字可由兼容的 SD 卡字体回退补全，但不得意外改变拉丁文字的 UI 度量。

代表性提交：`2d1148ff`、`619b6dcd`、`962c06ff`、`52514474`。

### 2. 阅读字体与 UI 字体使用独立的 SD CPFont 角色

- 阅读正文和设备 UI 分别选择独立的 SD 卡 `.cpfont` 字体族。
- 选择、替换、清除或加载失败时，一个角色不得静默覆盖另一个角色。
- 内置字体族仍是有效回退，但内置阅读字体族不能自动伪装成 SD 卡 UI 字体族。
- UI 回退字体必须具有可用的 CJK 覆盖，并保持适合界面度量的精确字号行为。
- 进入或退出字体目录、低内存恢复、重启以及重新扫描 SD 注册表后，字体选择都应保持不变。

代表性提交：`06c2686a`、`4c3c40ce`、`ab5cfb6d`、`dfc5fc54`。

### 3. 设备端字体目录与安全安装

- 设备支持多个字体仓库，包括配置为 owner/repository 的仓库以及 HTTPS manifest URL。
- 用户可浏览目录元数据、查看更新时间、预览远程字体族，并安装指定字号或完整字体族。
- 阅读字体族和 UI 字体族都采用分阶段、事务式替换；安装中断或失败时，不得破坏最后一个可用字体族。
- 通过 Web 上传字体族时也应遵循相同的事务原则。
- 下载文件必须有大小上限；必要时验证规范 CPFont v4 结构，并按 manifest 中的 SHA-256 校验值验证内容。
- 大型 manifest 采用流式解析；开始大型字体下载或渲染前，应释放 manifest 占用的内存。
- HTTPS 重定向、TLS 缓冲压力和 range 分段下载必须针对 ESP32-C3 的堆内存限制进行约束。
- 网络下载、校验、预览和安装过程中都必须能够取消。
- 低内存自恢复不得丢失已配置的 UI 字体族，也不得遗留临时预览或替换文件。

代表性提交：`66dd6348`、`8ea12890`、`0eb39e3e`、`4c2016f2`、`dc9e2f6b`、`6654c172`、`ccedc6ef`。

### 4. CJK 阅读排版与响应性

- EPUB 和 TXT 排版使用 CJK 感知的换行及标点黏连规则，不能套用依赖拉丁空格的假设。
- 两端对齐时，CJK 换行机会可作为可伸缩间隙，但不能插入可见的拉丁空格。
- 可选首行缩进约为两个汉字宽度，并参与分页和缓存失效判断。
- 较宽的 CJK 字号集合按实际已安装字号选择，不能依赖脆弱的序号槽位。
- SD 字形读取应批量化或预热，避免 CJK 页面上每个字符都触发一次随机 SD 寻址。
- 进入阻塞工作前，应先把索引状态显示到屏幕上。
- 章节构建、字形收集、图像解码、灰度渲染、索引和页面渲染都应能在安全边界取消。
- 输入和 activity 切换优先于过期后台工作；过期渲染不得随后覆盖新界面。

代表性提交：`4401cf40`、`15a7959a`、`a3e39099`、`d10e84cb`、`0db37e73`、`775ef4cc`。

### 5. 深色模式显示正确性

- 深色模式下所有可见更新都使用 `DarkRedrive`，包括普通翻页、恢复或降级路径、弹窗、休眠切换和低内存路径。
- 不能因为上游浅色模式路径使用 `HALF_REFRESH` 或普通 `FAST_REFRESH`，就让深色模式自动落入同一刷新方式。
- 局部或窗口更新应使用深色重驱动窗口路径，并把逻辑窗口正确转换为面板物理坐标。
- 阅读图像必须保留正确极性：深色背景可以反相，但封面或正文图片不能因此被重复反相。
- 裁切封面的完整边界必须被填满，不能留下上一帧的边缘像素。

代表性提交：`76c0a1bc`、`d720891b`、`d92649d5`、`489e028a`、`2b79de3d`。

### 6. 完整 UI 纵向倒置与方向感知输入

- 阅读方向和 UI 方向是两个独立持久化设置。
- 阅读器支持完整方向集合；普通 UI activity 则有意只支持纵向和纵向倒置。
- UI 倒置适用于整个界面，而不只是阅读器：首页、设置、对话框、键盘、Wi-Fi、字体目录和更新界面都必须按 UI 方向进入。
- 输入映射依据屏幕实际渲染方向，而不是可能已过期的阅读方向设置。
- 倒置时，按键提示、安全区域、电池与状态栏位置、选择项更新以及触摸到逻辑坐标的映射都必须正确。
- 不得为了“简化”而把两个设置合并为一个枚举，也不能让首页继承阅读器的横屏方向。

代表性提交：`106af11f`、`47b838ff`、`78154ba9`、`39889436`。

### 7. 延迟且可取消的首页封面处理

- 缺失封面需要进行昂贵处理时，首页也应先进入可交互状态。
- 封面缩略图生成应延迟执行，可在输入或 activity 变化时取消；已有有效缓存时应直接复用。
- 渲染代次和快照必须阻止过期封面任务在导航或几何尺寸变化后继续绘制。
- 局部选择更新应建立在已知的面板基线上，并只更新安全区域。
- 深色模式下，局部更新期间的封面极性和缓冲恢复必须正确。
- 缓存未命中或渲染中断时，应退化为完整可用的首页，而不是留下只画了一半的卡片。

代表性提交：`27ae3243`、`e75102a4`、`9b27173a`、`9beff5d0`、`5f9854d8`。

### 8. 保持响应的 Web 与上传路径

- 长时间 HTTP、WebDAV 和文件列表操作应适时喂看门狗或与任务看门狗安全协调，并在适当位置 `yield()`。
- 可能晚于 handler 返回才执行的 Web 响应必须持有有效状态，不能在延迟回调中捕获短生命周期缓冲区或对象。
- 设置页数据加载和响应生成应保持非阻塞或足够短，不得长期阻塞主循环及显示、输入处理。
- 上传数据以有界缓冲区流式写入存储，并保留低内存路径；不得要求与文件等大的 RAM。
- 不完整、超时、超限或失败的上传不得替换原有有效文件。
- Web、WebDAV、渲染、字体和持久化访问 SD 卡时，都必须遵循项目的串行化和加锁规则。

代表性提交：`a946c83a`、`27ec21db`、`128d5236`、`f6deae44`。

### 9. Wi-Fi 陈旧扫描恢复与 CJK 地区热点发现

- 每次新的异步扫描开始前，都应清除 Arduino Wi-Fi 层遗留的旧扫描状态。
- 连接失败、扫描中断或手机热点发生变化后，无需重启即可恢复扫描。
- 关联接入点前，以国家代码 `CN` 作为扫描初始域，使信道 12 和 13 仍可被发现。
- 必须保持 IEEE 802.11d 开启，使无线电能够采用接入点广播的监管域。
- 不得把这段逻辑改成永久监管域锁定，也不能把它当作“多余的地区常量”删除。

代表性提交：`accf1ee0`。

### 10. SD 字体、文件浏览性能与 SD 串行化

- FileBrowser 的列表热路径应避免反复进行完整路径或文本处理以及不必要的 SD 读取。
- SD 卡 UI 字体和阅读字体应保留缓存及预热行为，以限制随机访问和堆内存抖动。
- 与共享 SD 状态交互的文件关闭和打开顺序必须保持串行化；看似无害的提前关闭也可能与其他任务竞争。
- 长目录遍历和文件复制应周期性让出执行权并喂看门狗。
- 错误或取消路径必须释放字体和文件资源，且不能让注册表或 UI 字体状态失去一致性。

代表性提交：`16a59f4a`、`361aee32`、`c9aad6db`、`f6deae44`。

### 11. SD 固件、恢复模式与安全上传

- 用户可通过正常设置流程从 SD 卡安装固件。
- 普通 UI 路由不可用时，可在启动时按住文档规定的组合键，直接进入 SD 固件选择界面。
- 独立恢复环境及其打包流程必须保持可构建；参见 [SD 恢复固件](recovery-firmware.md)。
- 烧录前必须验证固件图像格式、目标芯片或设备、分区兼容性和安全大小。
- 上传与安装代码必须保留所需的 bootloader、分区表、factory 和双 OTA 布局约束。
- 安装成功后应启动目标 OTA 图像；失败时设备必须仍可恢复，并显示有用的错误信息。
- 固件传输必须采用流式、看门狗安全的实现，不能依赖一次性大块内存分配。

代表性提交：`5717374e`、`bf796a63`、`3e993191`、`e0ff0c9a`。

### 12. 持久化设置兼容性与 Calibre 清理

- 已保存设置属于兼容性边界：必须保留 JSON 键名、枚举数值含义、默认值、负数 SD 字体 ID 及迁移行为。
- 阅读方向和 UI 方向索引、休眠画面枚举顺序、键盘布局位以及字体角色选择尤其不能改变。
- 新字段必须具有向后兼容的默认值，并登记到设置 schema 或列表中。
- 为保持响应性，阅读进度和崩溃恢复写入可以延迟，但必须在深度休眠或其他持久化边界前完成。
- Calibre 连接界面不得显示旧会话或已移除认证流程遗留的管理令牌。

代表性提交：`6e4d0e53`、`0299a89c`、`ee3d714d`、`b0049cba`。

## 合并不变量

以上条目描述用户得到的功能。下列实现级不变量用于确保这些功能不被破坏：

1. 生成文件必须继续由生成器维护。修改翻译 YAML、字形输入或生成脚本后再重新生成。
2. 阅读字体和 UI 字体的 ID 与状态在设置、注册表扫描、renderer 初始化、预览、安装和回滚全流程中保持独立。
3. 字体包只有在下载完整、大小与哈希验证通过、CPFont 验证通过并完成原子或分阶段替换后才能启用。
4. Manifest 和字体下载必须具备明确字节上限、取消检查、看门狗维护及有界内存流式处理。
5. 深色模式可见刷新必须显式进入缓冲区或窗口 `DarkRedrive`；不能隐式回退到浅色模式策略。
6. 所有支持方向下，都要保留逻辑到物理窗口转换以及图像极性。
7. 长时间渲染、索引和封面任务必须携带渲染代次或取消谓词，并在提交 framebuffer 前再次检查。
8. 主循环输入轮询不得被放到阻塞渲染、网络、显示等待或 SD 操作之后。
9. 共享 SD 操作遵循 `HalStorage` 和项目既有锁约定；避免多个任务直接并发持有原始 SD handle。
10. 持久化枚举值和 JSON 键名属于数据格式 API，即使对应 C++ 声明看起来是私有实现。
11. 固件写入必须先验证再擦除或写入，并保持受支持 Xteink 硬件的启动与分区契约。
12. 敏感或会话派生的 Web、Calibre 值必须在所属会话结束时清除。

## 精简的合并后检查表

- [ ] 构建简中和繁中发布环境；从源输入重新生成 i18n 与 CJK UI 字体。
- [ ] 分别以英文、简中、繁中、日文启动，检查首页、设置、字体目录、Wi-Fi、更新、错误页和对话框有无缺字。
- [ ] 为阅读和 UI 选择不同 SD 字体族；重启、进出目录并模拟替换失败，确认两个角色都能保留。
- [ ] 从至少两个仓库预览和安装；测试取消、错误 SHA-256、无效 CPFont、安装中断和低堆内存。
- [ ] 打开 CJK 密集的 EPUB/TXT，测试标点换行、两端对齐、双字宽首行缩进、索引状态及页面工作取消。
- [ ] 测试浅色与深色翻页、图片、封面、休眠、弹窗、低内存降级和局部窗口更新，检查背景发白或极性错误。
- [ ] 分开测试阅读旋转与 UI 纵向/纵向倒置，检查提示、按键、触摸逻辑坐标和首页方向。
- [ ] 首页缺封面时立即操作导航，确认输入可取消旧任务，且旧封面不会稍后覆盖当前界面。
- [ ] 使用设备的同时压力测试 Web 文件列表、设置、WebDAV 和上传，检查看门狗、堆内存、残缺文件清理及 SD 串行化。
- [ ] 热点连接失败后重新扫描，并确认无需重启即可发现信道 12/13 的热点。
- [ ] 测试 SD 固件安装、启动组合键恢复入口、无效或错误设备图像，以及成功重启进入新固件。
- [ ] 加载合并前的设置和状态，验证枚举含义与字体 ID；进入深度休眠并确认进度和恢复状态已经提交。
- [ ] 进入和退出 Calibre 连接流程，确认界面不会显示陈旧管理令牌。
- [ ] 接受合并前运行格式化、静态分析、默认构建和相关主机端契约测试。

## 维护本文档

只有在某项分支特性被有意删除、替换，或上游已经提供经过等效测试的实现时，才更新对应说明。
与其记录一长串修复提交，不如保留一个代表性提交和最小范围的高风险路径。
三个语言版本应保持语义一致；文件改名时必须重新验证顶部导航链接。
